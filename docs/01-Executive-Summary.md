# 1. Executive Summary

## 1.1 Назначение

**SucheWohnung** — это веб‑платформа агрегации объявлений о квартирах на немецком рынке недвижимости. Система непрерывно собирает объявления с различных порталов (через API там, где он есть, и через web‑scraping там, где его нет), нормализует данные, устраняет дубликаты, сопоставляет каждое объявление с поисковыми профилями пользователей и моментально доставляет подходящие варианты в Telegram.

Рынок аренды квартир в крупных городах Германии (Берлин, Мюнхен, Гамбург, Франкфурт, Кёльн) характеризуется **высокой конкуренцией и скоростью**: хорошие объявления исчезают в течение нескольких часов. Ключевая ценность продукта — **минимизация задержки между публикацией объявления и уведомлением пользователя**.

## 1.2 Ключевая ценность

| Проблема пользователя | Решение SucheWohnung |
|----------------------|----------------------|
| Нужно вручную мониторить 5–10 сайтов | Единый агрегатор всех источников |
| Хорошие квартиры исчезают за часы | Уведомления в реальном времени: SLO p95 < 60 c, hard-alert при > 5 мин |
| Дубли одного объявления на разных порталах | Кросс‑портальная дедупликация |
| Сложные комбинации фильтров недоступны | Гибкая система фильтров + несколько профилей |
| Спам и нерелевантные предложения | Точный матчинг + только уникальные уведомления |

## 1.3 Подход к разработке

Проект реализуется в **три этапа**, каждый из которых даёт работающий инкремент:

- **Этап 1 — Базовая платформа.** Backend, frontend/admin, БД, авторизация, Telegram‑бот, система уведомлений, конфигурация фильтров. На этом этапе данные могут поступать из мок‑источника.
- **Этап 2 — Первая интеграция.** Подключение одного реального источника (рекомендуется ImmoScout24 или Immowelt), полный pipeline: сбор → валидация → дедупликация → матчинг → уведомление.
- **Этап 3 — Масштабирование.** Plugin Architecture позволяет добавлять новые источники (API‑коннекторы и парсеры) **без изменения ядра**. Цель — масштабирование до десятков источников.

## 1.4 Архитектурная философия

> **«Modular Monolith first, Microservices later»**

На старте система — модульный монолит с чёткими внутренними границами модулей и фоновыми воркерами. Это даёт скорость разработки и простоту эксплуатации при малой команде. Границы модулей спроектированы так, что любой модуль (особенно интеграции и нотификации) может быть вынесен в отдельный сервис без переписывания, когда нагрузка этого потребует.

Интеграции с источниками с самого начала строятся как **плагины** за единым интерфейсом `SourceConnector`. Ядро ничего не знает о конкретных сайтах — оно работает с нормализованной моделью объявления.

## 1.5 Целевые метрики успеха (KPI)

| Метрика | Целевое значение (MVP) | Целевое значение (Scale) |
|---------|------------------------|--------------------------|
| Задержка «публикация → уведомление» | p95 < 60 c, hard-alert > 5 мин | p95 < 60 c, дальнейшая оптимизация по источникам |
| Точность дедупликации | > 95 % | > 98 % |
| Доля ложных уведомлений (не соответствующих фильтрам) | < 1 % | < 0.5 % |
| Uptime | 99.5 % | 99.9 % |
| Кол-во поддерживаемых источников | 1 | 20+ |
| Время добавления нового источника | — | < 3 рабочих дней |

## 1.6 Границы проекта (Scope)

**В рамках проекта:**
- Сбор и нормализация объявлений об аренде/продаже квартир.
- Поисковые профили, матчинг, Telegram‑уведомления.
- Веб‑интерфейс пользователя и админ‑панель.
- GDPR‑совместимая обработка персональных данных.

**Вне рамок (на текущей фазе):**
- Заключение сделок / бронирование квартир внутри платформы.
- Платёжная система и подписочная монетизация (заложена архитектурно, реализуется позже).
- Мобильные нативные приложения (iOS/Android) — Telegram покрывает мобильный сценарий.
- Юридическое посредничество между арендатором и арендодателем.

## 1.7 Юридический контекст (важно)

Сбор данных с немецких порталов недвижимости связан с правовыми рисками: многие сайты (в т.ч. ImmoScout24) **запрещают автоматический сбор в ToS** и применяют технические меры защиты. Документ предписывает:
- Приоритет официальных API и партнёрских соглашений.
- Соблюдение `robots.txt`, rate‑limiting и «вежливого» поведения скрейперов.
- Хранение и обработку персональных данных строго по GDPR.

Детали — в разделах [Security & GDPR](./13-Security-GDPR.md) и [Risk Analysis](./17-Risk-Analysis.md).
