# 2. Business Requirements

## 2.1 Заинтересованные стороны (Stakeholders)

| Роль | Интерес |
|------|---------|
| **Конечный пользователь (арендатор/покупатель)** | Быстро находить релевантные квартиры, не пропускать выгодные варианты. |
| **Администратор платформы** | Управлять источниками, пользователями, следить за здоровьем системы. |
| **Владелец продукта (Product Owner)** | Рост базы пользователей, удержание, будущая монетизация. |
| **Команда разработки** | Понятная архитектура, низкая стоимость поддержки, простота добавления источников. |
| **DPO / юрист** | Соответствие GDPR и ToS источников. |

## 2.2 Бизнес‑цели

- **BG-1.** Предоставить пользователям самый быстрый в Германии канал уведомлений о новых квартирах.
- **BG-2.** Покрыть основные порталы недвижимости (ImmoScout24, Immowelt, Kleinanzeigen, Immonet, WG‑Gesucht и др.).
- **BG-3.** Обеспечить такую архитектуру, чтобы добавление нового источника было дешёвой и быстрой операцией.
- **BG-4.** Заложить фундамент для будущей монетизации (premium‑подписки: больше профилей, приоритетные уведомления, фильтр по новостройкам и т.д.).
- **BG-5.** Обеспечить юридическую устойчивость (GDPR, ToS).

## 2.3 Бизнес‑правила (Business Rules)

| ID | Правило |
|----|---------|
| BR-1 | Пользователь получает уведомление **только один раз** по каждому уникальному объявлению в рамках одного профиля. |
| BR-2 | Объявление считается дубликатом, если совпадает по нормализованному адресу + площади + цене (в пределах допуска) с уже существующим. |
| BR-3 | Бесплатный тариф: до **3 поисковых профилей**. Premium: до 20 (значение конфигурируемо). |
| BR-4 | Уведомления отправляются только по активным профилям с включёнными нотификациями. |
| BR-5 | Объявление, исчезнувшее из источника, помечается как `inactive`, но история сохраняется. |
| BR-6 | Персональные данные пользователя удаляются по запросу (Right to Erasure) в течение 30 дней. |
| BR-7 | Скрейпинг источника останавливается автоматически при превышении порога ошибок (circuit breaker). |
| BR-8 | Один Telegram‑аккаунт привязывается к одному пользовательскому аккаунту. |

## 2.4 Пользовательские роли и права

| Роль | Возможности |
|------|-------------|
| **Guest** | Регистрация, просмотр лендинга. |
| **User** | Создание/редактирование профилей поиска, управление подписками и уведомлениями, просмотр найденных объявлений. |
| **Premium User** | Всё что User + расширенные лимиты и приоритетные уведомления. |
| **Admin** | Управление пользователями, источниками, мониторинг, логи, очереди, статистика. |
| **Super Admin** | Всё + управление ролями, доступ к системным настройкам и секретам. |

## 2.5 User Stories (ключевые)

### Эпик: Поиск и уведомления
- **US-1.** Как пользователь, я хочу задать город, цену и количество комнат, чтобы получать только подходящие квартиры.
- **US-2.** Как пользователь, я хочу иметь несколько профилей поиска (например, «для себя» и «для родителей»), чтобы разделять критерии.
- **US-3.** Как пользователь, я хочу мгновенно получать уведомление в Telegram с фото, ценой и ссылкой, чтобы быстро откликнуться.
- **US-4.** Как пользователь, я хочу временно отключать уведомления по профилю, не удаляя его.
- **US-5.** Как пользователь, я хочу фильтровать по «без комиссии» и «разрешены животные», чтобы видеть только релевантные варианты.

### Эпик: Управление подпиской
- **US-6.** Как пользователь, я хочу привязать свой Telegram через одноразовый код, чтобы начать получать уведомления.
- **US-7.** Как пользователь, я хочу видеть список своих активных профилей прямо в Telegram командой `/profiles`.

### Эпик: Администрирование
- **US-8.** Как админ, я хочу видеть статус каждого парсера (работает / упал / заблокирован), чтобы быстро реагировать.
- **US-9.** Как админ, я хочу видеть статистику: сколько объявлений собрано, сколько уведомлений отправлено, сколько активных пользователей.
- **US-10.** Как админ, я хочу включать/отключать источник одним переключателем без деплоя.

## 2.6 Критерии приёмки MVP (Этап 1 + 2)

- ✅ Пользователь может зарегистрироваться, привязать Telegram, создать профиль поиска со всеми требуемыми фильтрами.
- ✅ Система собирает объявления как минимум с одного реального источника.
- ✅ Данные валидируются и дедуплицируются.
- ✅ Подходящие объявления приходят в Telegram в требуемом формате.
- ✅ Админ видит дашборд со статусом источника и базовой статистикой.
- ✅ Система соответствует базовым требованиям GDPR (согласие, удаление данных).
