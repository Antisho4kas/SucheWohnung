## 6.2 Обоснование ключевых решений

### 6.2.1 Почему Node.js/TypeScript, а не Python

Скрейпинг исторически ассоциируется с Python (Scrapy). Но:
- Бóльшая часть современных порталов недвижимости — **SPA на JS**, отдающие данные через внутренние JSON‑API. Перехват этих ответов удобнее всего делать через Playwright в Node.
- **Единый язык** для frontend, backend, бота и скрейперов снижает когнитивную нагрузку и стоимость поддержки.
- Очереди (BullMQ) и Telegram (grammY) — первоклассные именно в Node.
- TypeScript даёт строгую типизацию контрактов между модулями/коннекторами.

> Если в будущем понадобится тяжёлый ML/NLP (например, классификация объявлений), под него можно ввести отдельный Python‑сервис, общающийся через очередь — архитектура это позволяет.

### 6.2.2 Почему PostgreSQL, а не MongoDB

- Данные сильно реляционные (users ↔ profiles ↔ matches ↔ listings), нужны транзакции и целостность.
- **JSONB** покрывает потребность в гибких/сырых полях источников без отказа от схемы.
- **PostGIS** решает радиусный поиск нативно.
- Зрелые инструменты бэкапа/PITR.

### 6.2.3 Почему Redis + BullMQ, а не Kafka/RabbitMQ

- Объёмы (тысячи задач/мин) полностью покрываются BullMQ.
- BullMQ даёт **repeatable jobs** (планировщик), задержки, приоритеты, rate‑limit per queue, retries/backoff, DLQ — ровно то, что нужно.
- Redis уже нужен как кэш → меньше движущихся частей.
- Kafka оправдан при event‑sourcing/огромных потоках — избыточен на текущих масштабах (можно ввести позже, не ломая контракты событий).

### 6.2.4 Почему NestJS (modular monolith)

- Модули Nest = готовые границы будущих сервисов.
- DI и слои (Guards, Interceptors, Pipes) убирают бойлерплейт auth/validation/logging.
- Лёгкая интеграция с BullMQ, Prisma, OpenTelemetry.

### 6.2.5 Playwright + Cheerio (двухуровневый скрейпинг)

- **Cheerio** — для статических страниц и уже полученного HTML/JSON (быстро, дёшево, без браузера).
- **Playwright** — только когда нужен реальный рендеринг JS/динамический контент. Дороже по ресурсам, поэтому применяется выборочно (стратегия «cheap path first»).

## 6.3 Версионирование и зависимости

- Зафиксированные версии (`package.json` + lockfile), Renovate‑бот для обновлений.
- Контейнеры на пиннованных базовых образах (`node:22-bookworm-slim`).
- SBOM генерируется в CI (supply‑chain security).
