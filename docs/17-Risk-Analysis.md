# 17. Risk Analysis

Оценка: Вероятность (P) × Влияние (I), по шкале Low/Med/High.

| ID | Риск | P | I | Стратегия митигации |
|----|------|---|---|---------------------|
| R1 | **Блокировка скрейперов** (IP‑бан, CAPTCHA, Cloudflare) | High | High | Пул резидентных прокси, ротация, троттлинг, человекоподобное поведение, headful Playwright, экспоненциальный backoff, мониторинг 403/429, fallback на ручную проверку коннектора |
| R2 | **Дрейф HTML/структуры сайта** ломает парсер | High | Med | Контрактные «golden file» тесты на снапшотах HTML, алерты `schema_drift`, селекторы вынесены в конфиг коннектора, быстрый патч‑процесс |
| R3 | **Юридические/ToS‑риски скрейпинга** | Med | High | Юридическая экспертиза по каждому источнику; приоритет официальным API/партнёрствам; уважение `robots.txt` там, где обязательно; хранение ссылок, а не перепубликация контента; GDPR‑комплаенс |
| R4 | **Изменение/закрытие API источника, смена лимитов** | Med | High | Версионирование коннекторов, мониторинг квот, graceful degradation, абстракция через Connector Contract |
| R5 | **Утечка персональных данных пользователей** | Low | High | Шифрование, минимизация данных, RBAC, аудит, пентесты, GDPR‑процессы |
| R6 | **Дубликаты/спам уведомлений** раздражают пользователей | Med | Med | Многоуровневая дедупликация, идемпотентность отправки, rate‑limit на пользователя, дайджест‑режим |
| R7 | **Telegram Bot API rate limits / блокировка бота пользователем** | Med | Low | Глобальный троттлинг (≤30 msg/s), обработка `403 bot blocked` → деактивация подписки, очередь с backoff |
| R8 | **Лавинообразный рост очередей** при всплеске объявлений | Med | Med | Автоскейл воркеров (KEDA), backpressure, приоритеты очередей, DLQ |
| R9 | **Стоимость инфраструктуры/прокси** растёт нелинейно с числом источников | Med | Med | Бюджетные алерты, оптимизация частоты опроса по «продуктивности» источника, кэширование |
| R10 | **Зависимость от ключевых людей** (знание коннекторов) | Med | Med | Документация, Connector SDK, контрактные тесты, парное программирование |
| R11 | **Ложные совпадения / низкое качество данных** | Med | Med | Скоринг качества, валидация Zod, нормализация единиц/гео, ручной QA‑sampling |
| R12 | **Дедлайн‑риск из‑за недооценки скрейпинга** | Med | Med | Этапность, mock‑коннектор для разблокировки платформы, буфер в оценках |

## Топ‑3 риска под постоянным контролем
1. **R1 — Блокировки** (ядро продукта зависит от доступа к данным).
2. **R3 — Юридические риски** (могут заблокировать целый источник/направление).
3. **R2 — Дрейф парсеров** (постоянные операционные издержки).
